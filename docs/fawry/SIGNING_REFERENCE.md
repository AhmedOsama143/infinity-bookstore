# Fawry Signature Reference

> **Source of truth for every SHA-256 signature this integration produces or verifies.** Do not edit a signature formula in code without updating this file, and do not edit this file without cross-checking the live Fawry docs.
>
> Live docs:
> - Express Checkout — Self-Hosted Checkout Button: <https://developer.fawrystaging.com/docs/express-checkout/self-hosted-checkout>
> - Server APIs (refunds, status, etc.): <https://developer.fawrystaging.com/docs/server-apis/server-apis-overview>

## Conventions

- **Hash**: SHA-256, lowercase hex, UTF-8 encoding of the input string.
- **Money**: every monetary value is formatted to **exactly two decimal places** before concatenation (`Number(x).toFixed(2)` — e.g. `"10.00"`, never `"10"` or `"10.0"`). Applies to amounts and fees alike.
- **Optional fields**: when a field is "or empty", concatenate the literal empty string `""`. Do **not** insert any separator.
- **Comparison**: when verifying a Fawry-supplied signature, compare hex strings case-insensitively.

## 1. Charge request — signed by us, sent to Fawry via the JS plugin

Used by `lib/fawry/signing.ts → signChargeRequest`. This is the integration we chose in `INTEGRATION_PLAN.md §2` (Self-Hosted Checkout Button), **not** the server-to-server Charge API.

```
merchantCode
+ merchantRefNum
+ customerProfileId      (or "")
+ returnUrl
+ FOR EACH chargeItem (sorted ascending by itemId, lexicographic):
    itemId
  + quantity             (integer, no padding)
  + price                (two decimals)
+ secureKey
```

> ⚠️ This is **not** the formula sketched in `INTEGRATION_PLAN.md §6`. That summary describes the server-to-server Charge API (`paymentMethod` + top-level `amount`) which we are not using.

## 2. Charge response — verified on the browser-redirect return URL

Used by `lib/fawry/signing.ts → verifyChargeResponse`. Fawry attaches these as URL query parameters when redirecting the customer back.

```
referenceNumber          (or "")
+ merchantRefNumber
+ paymentAmount          (two decimals)
+ orderAmount            (two decimals)
+ orderStatus
+ paymentMethod
+ fawryFees              (two decimals, or "" if absent)
+ shippingFees           (two decimals, or "" if absent)
+ authNumber             (or "")
+ customerMail           (or "")
+ customerMobile         (or "")
+ secureKey
```

> The redirect-back URL is tamper-prone. Even with a valid signature, treat this as a UX cue only — the **webhook** is the authoritative source of order state. See `INTEGRATION_PLAN.md §3`.

## 3. Server Notification V2 (webhook) — verified on `/api/fawry/webhook`

Used by `lib/fawry/signing.ts → verifyCallback`. Field name is `messageSignature` in Fawry's payload.

```
fawryRefNumber
+ merchantRefNumber
+ paymentAmount          (two decimals)
+ orderAmount            (two decimals)
+ orderStatus
+ paymentMethod
+ paymentRefrenceNumber  (or "")    -- note: Fawry's spelling, not ours
+ secureKey
```

## 4. Status query — signed by us, sent to Fawry's `GET /payments/status/v2`

Used by `lib/fawry/signing.ts → signStatusRequest`. Slice 7 wires the actual call so the result page can reconcile when the webhook is delayed.

```
merchantCode
+ merchantRefNumber
+ secureKey
```

## 5. Refund — signed by us, sent to Fawry's server-to-server refund API

Used by `lib/fawry/signing.ts → signRefund`. Slice 10 wires the actual API call.

```
merchantCode
+ fawryRefNumber
+ refundAmount           (two decimals)
+ reason                 (or "")
+ secureKey
```

## Things that will burn you

- **Item sort order** in (1) is part of the signature. The cart UI may store items in arbitrary order; sort lexicographically by `itemId` before signing.
- **`paymentRefrenceNumber`** in (3) is misspelled in Fawry's docs and payload (missing the second `e`). Mirror their spelling — do not "correct" it.
- **Empty vs missing**. An optional field that is missing from Fawry's payload must concatenate as `""`, not `"null"`, not `"undefined"`.
- **Trailing whitespace** in env vars. `FAWRY_SECURE_KEY` ending with `\n` from a copy-paste produces every-request-fails-no-error. Strip on read.
